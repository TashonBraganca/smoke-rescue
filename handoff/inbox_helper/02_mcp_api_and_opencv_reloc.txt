B. OpenCV relocalization upgrade, research then build (technical depth; due 26 Oct 10:00 IST)
   Our place matcher fits a 2D rigid transform with our own RANSAC; two OpenCV alternatives lost on real TUM data (see
   data/evidence/real_data_check_25oct.txt, handoff/fence_fix_report_25oct.txt). Research and test, on the same TUM harness
   (tools/real_data_check.py, tools/rigid_fit_compare.py), held-out split reported first, ship only if it wins on recall,
   wrong poses and false accepts:
   1. PnP relocalization, the method ORB-SLAM uses: partner keyframe 3D points vs own keyframe 2D keypoints, solved with
      cv2.solvePnPRansac (SOLVEPNP_SQPNP / USAC_MAGSAC flags available in OpenCV 5), then project to the planar link. Own
      keypoints' pixel coordinates are local (no radio change); the payload stays as is.
   2. Better matching: mutual nearest neighbour (crossCheck), and, if available in the installed OpenCV, a better binary
      descriptor at the same 32 bytes (check cv2.xfeatures2d / BEBLID / TEBLID availability; if contrib is missing say so).
   3. Temporal consistency: accept a link only when consecutive keyframe matches agree (the brain already requires two;
      measure what that alone does to wrong poses on TUM sequences).
   RunPod may be used for parameter sweeps under the same rules (own folder, delete afterwards).
