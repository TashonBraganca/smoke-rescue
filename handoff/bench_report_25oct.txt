Headless benchmark: generator, runner and scorer (25 Oct 2026, a coding agent from opencv-a2; brief handoff/brief_bench_25oct.txt)

Files
  tools/bench/make_requests.py   writes worlds, fire files and one request JSON per run, plus manifest.json
  tools/bench/check_requests.py  proves each variant differs from full in exactly its one intended key, and seeds differ
  tools/bench/run_all.sh         runs every request with the built HeadlessRunner.dll, N in parallel, skips finished runs
  tools/bench/score_bench.py     scores the runs (evaluator side only), writes <bench>/score.txt and <bench>/score.json

How to run the full benchmark (30 houses x 3 seeds x 4 variants = 360 runs, duration_s 600)
  cd /Volumes/Tashon/opencv/smoke-rescue
  brain/.venv/bin/python tools/bench/make_requests.py data/runs/bench_25oct
  brain/.venv/bin/python tools/bench/check_requests.py data/runs/bench_25oct
  DOTNET=/Applications/Unity/Hub/Editor/6000.6.6f1/Unity.app/Contents/Resources/Scripting/DotNetSdk/dotnet \
    sh tools/bench/run_all.sh data/runs/bench_25oct/requests 6
  nice -n 10 brain/.venv/bin/python tools/bench/score_bench.py data/runs/bench_25oct
On Linux: leave DOTNET unset if `dotnet` (8.0 runtime) is on PATH, or set it; set HEADLESS_DLL if the runner is not at
tools/headless/bin/HeadlessRunner.dll. run_all.sh runs each job under `nice -n 10` (NICE overrides). Rerunning run_all.sh
skips every run whose result.json exists, so an interrupted benchmark resumes. A run that crashed leaves running.marker;
run_all.sh lists it as "stale marker" in <bench>/logs/failures.txt and the simulator will skip it until that marker is
deleted by hand. Per-run logs are in <bench>/logs/<run_id>.log.
Run time: at 4 in parallel on this Mac a 60 s run took 27 to 71 s of wall time (one-robot runs about half). I have not
timed a 600 s run; if wall time scales with simulated time, 360 runs at 6 in parallel is several hours. That is an
extrapolation, not a measurement.

robot_collision true, capsule_walls true, settings.mission_time_limit_s 480)

  no_radio   world key radio.range_m = 0. The simulator delivers a message only when distance <= range_m, so none arrive.
  one_robot  world key robots: robot_B removed (robot_A only).
  baseline   world identical to full. Request settings: room_memory false, door_claims false, room_entered_near_seat false,
             room_memory_same_space false, leave_waits_for_team false, walk_out_past_fire false, end_clear_way_out_m 0.
             All seven are BrainConfig fields (checked in BrainConfig.cs); the simulator throws on an unknown key, and
             both validation baseline runs completed and echo all seven keys in result.json settings.

Fire-grid fix for the seeded houses (read this)
  The first validation attempt crashed all four random_5001 runs in FireSim: "Footprint and room edges must align to the
  fire grid." None of the 28 seeded houses fits the 0.25 m fire grid (footprints such as 18.843 x 15.027 m); the ranches do.
  So, for the fire solver only, make_requests.py writes <bench>/fires/floorplan_<house>_firegrid.json: a copy of the floor
  plan with the footprint, every room edge and each door's wall line moved to the nearest 0.25 m line (at most 0.125 m).
  The world the robots move in (walls, furniture, people, pads) is not changed. The fire therefore burns in rooms up to
  0.125 m off the drawn walls. I checked all 28 copies in Python against FireSim's own plan rules (grid, no overlap, doors
  cut their named boundaries, ignitions inside their rooms): 0 problems. Only random_5001 has actually been run with it.
  In the 60 s random_5001 runs the peak air at a robot was 20.0 to 20.3 C (no head start, fire just lit), so these runs do
  not show that the seeded-house fire grows as it should by 600 s. Check one 600 s seeded run's peak_air_c before trusting
  fire effects. The ranches use their own plans unchanged (peak air 37.6 to 40.6 C at 60 s, 320 s head start).

Scorer definitions (also in score_bench.py and score.json)
  rooms entered: evaluator rooms that contain any robot pose. coverage: usable floor on a 0.1 m grid (off furniture
  0.15 m or taller, 0.125 m clear of full-height walls, as tools/score_ranches.py) in the union of the robots' own_searched
  masks. people confirmed: people with a survivor_confirmed event within 1.5 m; false confirmations: events farther than
  1.5 m from every person; time to each person: first matching event. overlap: usable samples in both robots' own_searched
  masks over samples in either (2-robot variants only). all out: every robot ended outside every room in state complete
  after entering a room.
  T90 is a proxy. result.json holds only the final searched masks, so coverage over time is not recorded. T90 uses swept
  floor: usable samples within 2.0 m of a pose and in the same evaluator room, accumulated every 1 s. T90 = first time the
  team's swept floor reaches 90 % of the house ceiling, the largest final swept floor among that house's full runs (all
  seeds). Not reached counts as duration_s (censored), and score.json gives t90_reached per run. Because the ceiling comes
  from full runs, full is favoured on this metric by construction when there are few seeds.
  Aggregates: mean with a nested bootstrap 95 % CI (10,000 resamples, houses with replacement, then seeds within each house),
  houses weighted equally. Paired full minus variant per (house, seed) with the same bootstrap, and a Wilcoxon signed-rank p
  on per-house mean differences (houses are the independent units; with 1 or 2 houses p cannot go below 0.5).
  Seen vs unseen: a seeded house is seen if its number appears in any string of config/brain.json or config/perception.json
  or in data/evidence/*.txt. Result: 20 seen (5001, 5002, 5003, 5004, 5005, 5006, 5007, 5010, 5011, 5013, 5014, 5015, 5016,
  5017, 5020, 5021, 5022, 5023, 5027, 5028); unseen: 5008, 5009, 5012, 5018, 5019, 5024, 5025, 5026 and both ranches.
  All 125 matches are in config/brain.json reason strings; none in perception.json or data/evidence/*.txt. The full match
  list with context is at the end of this file. The grep is conservative: a seed mentioned only as a counterexample still
  counts as seen. The ranches were tuned on directly today (end_clear_way_out_m cites both), so calling them unseen follows
  the brief but is generous.

Caveats
  Headless has no rendered camera. YOLO and visual SLAM are not exercised; poses come from the simulator's motion and LiDAR
  model, and person confirmation uses the headless sighting model (in range, inside the camera's field, clear line of
  sight), not a detector on images. Smoke does not degrade sensing headless. These are benchmark results for the planning,
  team and room logic, not for perception.
  T90 is a swept-floor proxy, not searched coverage over time (see definitions).
  Seeded-house fire runs on a plan snapped to the 0.25 m fire grid, and its growth by 600 s has not been checked.
  The DLL is from 15:09 and not rebuilt; see "Runner used".
  The full 360-run benchmark has not been run. Only the 8 validation runs above exist.
  The validation scorer output follows, pasted unchanged from data/runs/bench_val_25oct/score.txt (git-ignored folder).
